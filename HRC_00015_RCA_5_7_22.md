## Root cause 1 — Critical: Decimal `//` is not mathematical floor (negative pools)

`allocate_physical_two_slice` computes:

```python
R = int(pv // pq)  # intended floor(avg)
```

For **Python `int`**, `//` is floor-toward-−∞. For **`decimal.Decimal`**, `//` follows
`divmod` where the remainder takes the dividend’s sign — i.e. **truncate toward zero**.

Example matching the production error exactly:

| | Value |
|--|--|
| pool_qty | 2 |
| pool_value | −3,894,157 |
| out_qty | 1 |
| exact avg | −1,947,078.5 |
| `Decimal //` (bug) | **−1,947,078** |
| true floor | −1,947,079 |
| `ROUND_HALF_UP(exact)` | −1,947,079 |
| `n_high = out_v − oq·R` | −1 → **AllocationError** |

Two-slice invariant `out_v ∈ [oq·R, oq·(R+1)]` requires mathematical floor. Negative
batch pools (qty>0, value<0) therefore fail closed incorrectly.

Also: `if abs(total) != out_v` compares magnitude to a **signed** `out_v`, so even some
negative-pool cases that get past `n_high` fail the slice-sum check.

### Why this RIV can hit the allocator

Physical Two-Slice rewrite is scoped to Delivery Note / Sales Invoice outwards.
Identity `13200112`@approved currently has SLE voucher types RECO/STE/PR only (no DN/SI).
Negative-pool math is still a latent production defect for any DN/SI (and for any future
scope expansion). Mid-RIV temporary negative pools are observed elsewhere in this database
(e.g. batch residuals with qty=0 value=−20; other items with qty>0 value≪0).

## Fix strategy (permanent)

1. **Allocator:** compute `R` with `ROUND_FLOOR`; treat `out_value_abs` as magnitude;
   keep rate×qty identity; add regression for the exact (−3894157, 2, 1) case.
2. **RIV negative / short pool:** keep fail-closed on live submit; during RIV, audit +
   fall through to integer SABE policy when pool_value < 0 (mirror short-pool policy).
3. **GL ±1:** ensure stock-valuation residual absorb covers Manufacture GL rebuilt from
   RIV; harden if absorb returns false for one-quantum IRR diffs.
4. **Tests:** allocator negative-pool; HRC-00015 scenario; GL residual absorb; campaign
   filter for restricted risk set.
5. **Restricted campaign:** only identity `13200112`@approved (+ required upstream
   deps / `MAT-STE-2026-41025` linkage) — not full 17,973 manifest.

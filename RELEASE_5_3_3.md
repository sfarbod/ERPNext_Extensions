# Release 5.3.3 — Manufacturing Valuation Contract

Package version: **5.3.3**.

Implements the approved Iran Manufacture overlay for two valuation gaps:

1. Component Scrap must use the transaction-local issued/consumption rate.
2. Main FG, Main Product Reject, Co-Product and Co-Product Reject generated by
   the same stage must share manufacturing cost **per equivalent production unit**.

---

## Gap 1 — Component Scrap issued rate

For a qualifying Component Scrap row:

`Component Scrap Rate = issued/consumption rate of that component on the same Manufacture voucher`

The overlay does **not** use:

- target Reject/Scrap warehouse valuation
- stale batch valuation
- Item.valuation_rate
- historical destination SLE valuation

Matching order:

1. Consumed rows on this voucher
2. Same Batch when deterministic
3. Weighted transaction-local issued rate for the matching item family
   (`Σ basic_amount / Σ transfer_qty`)
4. Z-code / `custom_main_item_code` fallback when valid

`allow_zero_valuation_rate` is only a temporary compatibility flag. After a
deterministic issued rate exists it is cleared. A second validate must not wipe
the rate back to zero.

A Manufacture is **not** economically healthy when Component Scrap is zero or
stale while the issued rate is positive.

Confirmed development shape (`MAT-STE-2026-37327` item `13200256`):

- issued rate `35,297 IRR`
- qty `7` → `247,079 IRR`

The same rule applies to every qualifying Component Scrap row on the voucher.

## Gap 2 — equivalent-unit Stage Output costing

Eligible Stage Outputs:

- `MAIN_FG`
- `MAIN_PRODUCT_REJECT`
- `CO_PRODUCT`
- `CO_PRODUCT_REJECT`

Not eligible: Component Scrap, unused returns, Transfer rows, process-loss
quantity, unrelated `OTHER_OUTPUT`, and finance-explicit Manual / `% of Component Cost` rows.

Formulas:

```
Equivalent Qty_i = Stock Qty_i × Physical Conversion_i × Explicit Factor_i
Material Rate_eq = Material Cost Pool / Total Equivalent Qty
Operating Rate_eq = Operating Cost Pool / Total Equivalent Qty
Value_i = Equivalent Qty_i × (Material Rate_eq + Operating Rate_eq)
```

Material Cost Pool = source-only consumed `basic_amount` − Component Scrap value
− explicitly excluded finance-configured output value.

Component Scrap keeps material value only and receives **no** operating cost.

Equivalence hierarchy:

1. Physical UOM conversion from existing Item UOM data
   (approved family: `1 BOX(2pfs) = 2 syringes`)
2. Explicit `custom_output_equivalent_factor` snapshotted on the voucher
3. **Block** — never assume silent `1:1`

Displayed Stock-UOM `basic_rate` values may differ when UOMs differ.
Equality is per equivalent unit, subject to IRR integer rounding.
Deterministic residual goes to Main FG.

Example: if the common rate is `R` per syringe, then

- `30500003` (1 syringe) `basic_rate = R`
- `20100067` (1 BOX = 2 syringes) `basic_rate = 2R`

## Job Card ↔ Stock Entry secondary-output contract

A Co-Product / By-Product / Additional Finished Good generated from a Job Card
must match that Job Card.

Mismatch raises `frappe.ValidationError` identifying the Job Card, expected
item, actual Stock Entry item, secondary type, and row.

`MAT-STE-2026-37031` (SE `30500003` vs Job Card `30300020`) is **blocked**
under this contract. The document is not auto-corrected.

---

## Contract version and historical documents

New and draft Manufacture documents adopt contract version `5.3.3` on
validate/save and snapshot:

- output class
- physical conversion
- equivalent factor / qty
- common UOM
- parent Co-Product
- header `custom_manufacturing_costing_contract_version`

Submitted historical documents **without** that stamp are not silently recosted
by RIV. RIV of a stamped v5.3.3 voucher reproduces the snapshotted economics
even if later Item UOM or BOM/Job Card factors change.

Existing drafts may reprice on the next save. They are not auto-submitted.
Mismatched Co-Products still block.

Historical submitted zero-rate Scrap/Co-Product cases are **not** repaired in
this release.

`iran_accounting.custom_fields.after_migrate`.

---

## Draft repricing impact

On the next validate/save of an **existing draft** Manufacture:

- Component Scrap currently at 0 / stale warehouse rate will move to issued rate
- Matching Co-Products will share equivalent-unit stage cost, including operating cost
- Job Card / Stock Entry secondary mismatches will **block save/submit**
- Missing UOM conversion and missing equivalent factor will **block** (no 1:1)

Submitted documents stay unchanged until a separately approved repair wave.
